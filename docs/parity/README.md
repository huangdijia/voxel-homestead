# Java 1.21.1 逐项内容审计基线

本目录列出固定数据源中的 **5,953 条内容记录**，每条都有 ID、计划阶段、局部实现映射、验收用例 ID 和可定位的来源。它是首份可复现的逐项审计清单，**不是 Minecraft Java 1.21.1 的官方全量清单，也不表示 5,953 个功能已经完成**。结构、维度等十类缺口见 [index.json](index.json) 的 `missing`，非数据行为见 [BEHAVIORS.md](BEHAVIORS.md)。本次没有下载或复用原版材质、声音、模型或游戏程序。

## 版本与来源

官方 [Java 1.21.1 发行说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-1) 发布于 2024-08-07，说明这是修复严重漏洞的热修复版本；它确认目标版本，但没有枚举全部注册表。前一版 [Java 1.21 发行说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21) 可追溯试炼密室、合成器、重锤等版本特性，但同样不是完整内容清单。不能用后续版本的新内容补入本目标。

逐项数据来自 [PrismarineJS/minecraft-data 的固定提交](https://github.com/PrismarineJS/minecraft-data/tree/abfaadb4c45e2968a98fc927d32f7c648962d8ad)：

- Git commit：`abfaadb4c45e2968a98fc927d32f7c648962d8ad`，提交时间 `2026-09-04T14:01:53Z`。
- 版本入口：同一提交的 `data/dataPaths.json` 中 `pc["1.21.1"]`，不是直接猜测所有文件都在 `1.21.1` 目录。
- `version.json` 确认 `minecraftVersion=1.21.1`、`majorVersion=1.21`、协议号 `767`。协议号只作来源标识，不表示本项目兼容原版协议。
- 原始 URL、实际版本目录、字节数及每个原始文件的 SHA256 全部固定在 [sources.lock.json](sources.lock.json)。本数据仓库根目录没有 `package.json`，因此没有编造 npm 包版本；以提交和文件哈希锁定。
- 这是该第三方数据项目自身的第一手发布数据，**不是 Mojang 官方认证**。其 [README](sources/README.md) 说明了多种提取来源，并声明 MIT 及历史来源许可说明；保留原文归属，不把原版游戏素材纳入该声明。

## 实现与验收字段

`implementation.status` 只表达自动映射发现的证据层次：

| 状态 | 含义 |
| --- | --- |
| `partial-unverified` | 本地注册表存在对应定义，行为、全部状态和浏览器验收尚未逐条核定。 |
| `definition-match-unverified` | 本地合成定义与源组合的类型、材料、形状/镜像和产物数量一致；尚未执行本条验收。 |
| `output-candidate-unverified` | 本地存在同产物配方，但材料或类型等没有严格对应；不能按已实现计算。 |
| `not-mapped` | 没有可自动确认的逐项映射；不代表已经全面检查全部模拟代码。 |

所有条目的 `acceptance.status` 均为 **`not-run`**，本基线的逐项验收通过数为 **0**。这不否定已有 M1 集成测试；它说明那些测试结果尚未按本目录每条目标、源码版本、浏览器和状态边界建立验收关联。脚本不会根据“测试文件存在”或“注册表出现”自动升级状态。

[local-evidence.json](local-evidence.json) 保存实际读取的 `registry.ts`、`recipes.ts`、`inventory.ts` 哈希、别名、配方定义及反向映射。例子包括 `log → minecraft:oak_log`、四段门定义 → `minecraft:oak_door`、多阶段作物 → 一个带 `age` 属性的方块。耕地、作物、锄、剪刀、水桶、堆肥桶等本轮新定义一律待验；繁殖属于行为条目，不能从猪羊注册表推断通过。

源合成表没有原版资源位置，因此每条 ID 是 `prismarine:recipe/<数值产物ID>/<原始组合记录SHA256前20位>`。保存源文件 JSON Pointer 可定位原记录；同一产物的木材变体不能当成不同的官方配方资源。当前本地木板的 1×1 有序配方与源无序记录没有被严格匹配；这是保守映射差异，不是已证明游戏不能合成木板。

本地存在、源域中没有的内容会留在 `unmatchedLocal`，例如直接使用的 `water` 物品；不会强行映射成 `water_bucket`。本地熔炼配方保存在 `smeltingRecipes`，状态为 `local-definition-reference-domain-missing`，不能混入仅有工作台组合的上游配方分母。

`stage` 是项目排期，不是来源事实或完成声明。M1 对应已有铁器生存范围；M2 默认安排主世界内容；M3 安排维度、红石和高级系统；M4 做跨系统与表现收尾。代码里的高级内容关键词分配是可复现的初步安排，`stageBasis` 含 `review-required` 的条目须在进入对应阶段前人工复核；跨域依赖可使条目提前实现。不能因为某记录被排到 M1 就声称 M1 已覆盖其原版全部变体。

## 每条验收如何执行

每条记录的 `acceptance.id` 是稳定用例 ID，`targetId` 是被测对象，`template` 和 `requiredChecks` 给出最低步骤。它们是**待执行的验收规格**，不是 5,953 个已经写好并通过的自动化测试。

| 模板 | 最低执行要求 |
| --- | --- |
| `blocks` | 在生存和创造中取得目标，按源属性逐个摆放/交互/破坏；核对碰撞、工具门槛、掉落与相邻更新；跨区块卸载和重载后保持正确状态。 |
| `items` | 取得目标，验证堆叠拆分和容器转移；使用、消耗、耐久、余留物与组件按目标定义检查；死亡掉落和存档回读守恒。 |
| `entities` | 验证目标生成、消失、移动/AI、交互、受伤、掉落与各变体；卸载和保存恢复后状态一致，不能只测试创建实体对象。 |
| `biomes` | 用固定种子定位目标群系内部和边界，核验地形/气候/特征/生成生物及资源可达性；重进世界不改变已有区域。 |
| `recipes` | 用本行材料和数量实际操作 UI；验证有序偏移/镜像或无序排列、错误材料、额外材料、产物数量、满背包和保存时的守恒。标签替代品必须由补齐的同版资源定义决定。 |
| `foods` | 检查目标食物的可食条件、耗时、饥饿/饱和变化、特殊效果、余留容器，保存和死亡后不复制或丢失。 |
| `enchantments` / `effects` / `attributes` | 逐等级/强度/持续时间验证获取、冲突/叠加、应用、移除和装备变化；真实行为变化与保存回读均需证据。 |
| `particles` / `sounds` / `instruments` | 触发目标事件，检查参数、分类、距离、设置以及原创视听表现；音符盒另验音高、乐器选择和红石触发。无需复用原版文件。 |

浏览器证据至少记录应用源码提交或哈希、目标版本、浏览器及版本、种子/夹具、步骤、断言和结果文件。Chrome、Edge、Safari 的实际操作分别记录；一个浏览器的结果不能自动外推。需通过的行为关联见 [BEHAVIORS.md](BEHAVIORS.md)。

## 复现与校验

使用项目已安装的 Node.js 与 TypeScript 依赖，不新增依赖、不启动游戏：

```sh
node scripts/build-parity-catalog.mjs
node scripts/build-parity-catalog.mjs --check --self-test
```

第一条从提交内缓存和当前本地注册表重新生成；第二条离线只读，验证原始来源哈希/大小、版本映射、逐项 ID 与用例 ID 唯一性、数量、阶段、状态、源指针、方块状态范围及生成文件是否过期。源码注册表变化后，`--check` 会失败并提示重新生成。

```sh
node scripts/build-parity-catalog.mjs --fetch --self-test
```

此命令只从锁定提交下载同一批 JSON/README，并在写入前校验原哈希和字节数；不升级来源，不下载游戏素材。`--check` 与 `--fetch` 不能同时使用。无时间戳进入生成产物，同一来源和本地源码快照可逐字节重建。

`--self-test` 用内存中的故障样本确认重复 ID、非法阶段、虚假验收通过、失效源指针和数量减少都会被拒绝，并验证配方镜像等价与材料数量差异。它验证的是清单生成器，不能代替游戏测试。本次校验记录见 [VERIFICATION.md](VERIFICATION.md)。
